### Consequences

- A machine with the old name installed has three leftovers: `.venv/bin/ros-manifest`, `.make/ros-manifest.done`, and the editable install of the distribution `ros-manifest` whose path points at the directory that no longer exists. The main checkout here has the first two (both exist); the editable install is the usual consequence of the Makefile rule and I did not inspect it. `make setup` runs the new stamp rule only because the new stamp is absent; the rule has to `pip uninstall -y ros-manifest` (tolerating "not installed") and remove `.venv/bin/ros-manifest`, or the adapter finds a command that fails on import and the hint sends the user to the target that does not exist any more.
- The adapter looks for `<main checkout>/.venv/bin/repos-manifest`. On a machine that has only the old command, its error says to run `make install-repos-manifest` (the hint for a resolver too old to know `--layout manifest-dir` too). That works. Naming the legacy path in the hint is optional; the issue lists "the install path a machine with the old name already installed needs", so decide and test one way.
- The cache directory name `.ros-manifest-cache` becomes `.repos-manifest-cache`: caches under the old name are orphaned (an extends clone is re-fetched, no data lost), and with the old `.gitignore` entry gone they show as untracked in any checkout where one was made. Note that in the PR.
- The environment variable `ROS_MANIFEST_GIT_TIMEOUT` becomes `REPOS_MANIFEST_GIT_TIMEOUT`. A user who set the old one silently gets the 60 s default. State it in the tool's README; the tool is a prototype with one user, so no fallback is needed.
- The roadmap check `file-exists src/repos_manifest/cli.py` in `tools/ros-manifest/docs/roadmap.md` is resolved against the sub-roadmap's Root, so the pointer row's Root cell (once 488 adds it) must be `tools/repos-manifest`; with the old Root the check reads a missing file and the row's other checks break too.
- Tests that fake the resolver (`test_ros2_colcon.sh` wrappers that write `$sb/.venv/bin/ros-manifest` and run `-m ros_manifest.cli`) must follow the rename, or they test a command the adapter no longer calls.
- History stays: `.agent/work-plans/` (many files) and the change-log rows of `docs/design.md`. Use a path-limited search-and-replace so they are not touched, then run the acceptance search and list what remains.
