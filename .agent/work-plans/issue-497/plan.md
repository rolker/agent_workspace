# Plan: repos-manifest: rename the tool's code, directory and command from ros-manifest

## Issue

https://github.com/rolker/agent_workspace/issues/497

## Context

The manifest tool lives in `tools/ros-manifest/` (package `ros_manifest`, command `ros-manifest`, distribution `ros-manifest`). The owner chose the new name `repos-manifest`; this is the first of seven issues (497 to 503) that build the new manifest design, and 498 rewrites the resolver on the new path. This issue is a pure rename: no change to what the tool reads, writes or does. Owner decisions of 2026-11-18 (progress.md Checkpoint): CI changes cover both places in `validate.yml` that name the tool and nothing else; the Issue Review's points are instructions for this plan; issue 488 lands first and this sweep then covers its files.

## Approach

1. **Start from a current base** — `git fetch origin`, then check `git merge-base --is-ancestor feature/issue-488 origin/main`. If 488 is on `main` (as of planning it is not: its branch is local and unpublished), `git merge origin/main` into this branch before the sweep. If it is not yet, stop and report to the owner that 488 is not on `main`; do not start the sweep (the owner chose 488 first so the path changes once). Re-run the same check at step 11.
2. **Move the directory and package** — `git mv tools/ros-manifest tools/repos-manifest`, `git mv tools/repos-manifest/src/ros_manifest tools/repos-manifest/src/repos_manifest`. Edit `pyproject.toml`: `name = "repos-manifest"`, script `repos-manifest = "repos_manifest.cli:main"`, any package path.
3. **Sweep the names** — path-limited search-and-replace (`ros-manifest` to `repos-manifest`, `ros_manifest` to `repos_manifest`, `ROS_MANIFEST_GIT_TIMEOUT` to `REPOS_MANIFEST_GIT_TIMEOUT`, `.ros-manifest-cache` to `.repos-manifest-cache`) over everything `git grep -il 'ros-manifest\|ros_manifest\|ROS_MANIFEST'` finds outside `.agent/work-plans/` and outside every change-log row of `docs/design.md` before the new one (no fixed line numbers; the rows shift when 488 merges). Take the list from that search, not from the issue text: the tool's source (`cli`, `emit`, `extends`, `__init__`) and the 9 test modules that name it (of 10 `.py` files in `tests/`); the tool's `README.md`, `docs/design.md`, `docs/prototype.md`, `tests/fixtures/p11/manifest.yaml`; `.agent/project_types/ros2_colcon/adapter.sh`, `.agent/projects.local.example`, `Makefile`, `.gitignore`, `docs/design.md`, `docs/manifest/design.md`, `docs/fork_parity.md`, `docs/roadmap.md`; the suites `.agent/scripts/tests/test_ros2_colcon.sh` (fake resolver at `$sb/.venv/bin/ros-manifest`, `-m ros_manifest.cli`), `test_register_project.sh`, `test_fresh_clone_no_project.sh` (stamp `.make/ros-manifest.done`). Three present-tense sentences are rewritten by hand, not replaced, because they say the code "still" carries the old name: `docs/manifest/design.md` near its top ("The tool's code and command still carry its earlier name"), the tool's `docs/design.md` near its top ("The prototype's command is still called `ros-manifest`") and the tool's `README.md` near its top ("its directory, command and Python package still carry that name"). Reword the first to say the tool is called `repos-manifest`; keep one sentence in the tool's documents (README) saying it was called `ros-manifest` until #497, and drop the other two or reword them without the old name.
   ADR-0022 (added by PR 504, #488; five mentions: three in its Context, two as current paths in its decision text): ADR-0008 lets an accepted ADR take link and path fixes, not rewording. Rename the two current-path mentions (`tools/ros-manifest/docs/design.md#<section>` and the part path) as broken-link fixes. The Context's three mentions (the tool's earlier path, and "installed by `make install-ros-manifest`") describe the state at decision time: keep them as history and list them in step 11; the PR records this choice. The same rule applies to the roadmap's pointer row (path and Root cell renamed, a live reference) and the planned row's prose naming `tools/ros-manifest` (a current path, renamed).
4. **Generated header** — `emit.py` writes `# Generated by ros-manifest` (lines 62 and 90); change both to `repos-manifest` and update `test_layout.py` (the line asserting the header). Do not touch `tests/fixtures/p11/expected/`: the 14 expected `.repos` files carry no header and `test_acceptance_p11.py` compares `strip_provenance_header(got) == want`. `git grep -n 'Generated by' -- .agent tools` (outside work plans) finds only `emit.py` and `test_layout.py`; the PR says: only `test_layout.py` compares the header text, the p11 test strips it, the adapter's `validate` compares resolved directories.
5. **Makefile** — rename target `install-ros-manifest` to `install-repos-manifest` (also in `.PHONY` and help lines), stamp to `$(STAMP)/repos-manifest.done`, prerequisite `tools/repos-manifest/pyproject.toml`, header comment. Make the stamp's recipe first remove the old install on a machine that has it: `$(VENV_BIN)/python3 -m pip uninstall --quiet -y ros-manifest || true` (venv pip only, ADR-0009), `rm -f $(VENV_BIN)/ros-manifest $(STAMP)/ros-manifest.done`, then install and touch the new stamp. No alias for the old target or command (it would fail the acceptance search). Run `make generate-skills` after the `.PHONY` rename so the `/make_install-repos-manifest` command exists locally; its output (`.claude/skills/make_*/`) is gitignored, so nothing from it is committed.
6. **Adapter hint** — the two hints already say `make install-repos-manifest` after the sweep; keep the hint as is (no legacy-path wording): a machine with only the old command is told to run the new target, which then removes the old install. A test in `test_ros2_colcon.sh` covers the not-installed hint with the new name.
7. **CI (`.github/workflows/validate.yml`)** — only these lines, inside the owner's "Yes, both jobs": in the adapter-tests job three lines (the step `name:` "Install ros-manifest (the resolver the ros2_colcon adapter calls)", `pip install -e tools/ros-manifest`, `ros-manifest --help`), and the tool's own job (job id `validate-ros-manifest`, its `name:`, step name, `pip install -e tools/ros-manifest[test]`, `pytest tools/ros-manifest/tests`). The job `name:`'s "(#267 prototype)" suffix stays. Nothing else in CI. `git diff -U0 .github` is pasted into the PR description as the full list of CI lines changed, naming the step-name line explicitly. Check that no required check names the old job id: as of the Plan Review `main` has no classic branch protection (404) and one ruleset `require_pr`; re-check with `gh api` before pushing, and tell the owner if one does.
8. **Docs and design** — in `docs/design.md`, by searching for the old name (not by line number): the manifest-route bullet under Registry and adapters, the `setup` verb-table row, the Rules project-names row; every change-log row before the new one keeps the old name as history, including 488's own row. Add one change-log row dated 2026-11-18 (section: Registry and adapters, Rules), "the tool is renamed repos-manifest (path, package, command, make target, stamp, env var, cache directory), no behaviour change", issue #497, with its Lines column filled from `wc -l docs/design.md` after the edit (the table's last column). `tools/repos-manifest/README.md` gets a short note: `ROS_MANIFEST_GIT_TIMEOUT` and `.ros-manifest-cache` are ignored after the rename (set `REPOS_MANIFEST_GIT_TIMEOUT`; an old cache directory can be deleted). The PR says the same, and that orphaned `.ros-manifest-cache/` directories show as untracked because the old `.gitignore` entry is gone.
9. **Tests, offline, and the acceptance check on the real tree** — pre-commit on changed files; `.venv/bin/pytest tools/repos-manifest/tests` after `pip install -e tools/repos-manifest[test]` in the venv (includes the p11 acceptance test, unchanged fixtures); the three shell suites; `.agent/scripts/validate_adapter.sh` for ros2_colcon (ADR-0011) if it runs offline. Then, with 488 merged, set the pointer row's Root cell in `docs/roadmap.md` to `tools/repos-manifest` (path cell `tools/repos-manifest/docs/roadmap.md`), run `.agent/scripts/sitrep_checks.sh --root .` and show the tool roadmap's `file-exists src/repos_manifest/cli.py` line ("The tool and its code carry the name repos-manifest") as `true`; run `.agent/scripts/check_design_anchors.sh` after the sweep and show it passes (488's citations into `tools/repos-manifest/docs/design.md#...` resolve). Per the memory rule for dispatched agents, no full ~10 min pre-commit suite; CI runs the suites.
10. **Sandbox proof of the migration** — in a scratch checkout of this branch under the scratchpad, build a venv with the old distribution installed (`pip install -e` of a copy of the old tree from `main`), plus `.make/ros-manifest.done` and `.venv/bin/ros-manifest`; delete the old tree path to mimic the rename; run `make setup` (or `make install-repos-manifest` if `setup` needs the network for git-bug; say which). Show after: `.venv/bin/repos-manifest --help` runs, `.venv/bin/ros-manifest` and the old stamp are gone, `pip show ros-manifest` fails, `pip show repos-manifest` succeeds, and the adapter's manifest route finds the command (the resolver-path test in `test_ros2_colcon.sh`). Paste the transcript into the PR description.
11. **Finish** — `git fetch origin`; run the acceptance search `git grep -n -i 'ros-manifest\|ros_manifest\|ROS_MANIFEST' -- . ':!.agent/work-plans'` on the branch and on `origin/main`; the only hits left are history: earlier change-log rows, the one "called `ros-manifest` until #497" sentence in the tool's documents, ADR-0022's Context sentences (step 3's ADR rule below) and this issue's own mentions; list them in the PR. Diff `origin/main` against the branch base for any file that names the old path (a late merge of 488 or another branch); if any, merge `origin/main` and sweep again. The PR description also gives 488's author the replacement command in case 488 does land second after all: `git grep -il 'ros-manifest\|ros_manifest'` on the rebased branch.

## Prior Art

Nothing new is being built. The stamp-file install rule (ADR-0007) and `.venv` rule (ADR-0009) are used as they are. A compatibility alias for the old command was considered and rejected: it keeps the old name alive and fails the acceptance search; the tool has one user.

## Serves

Flexibility (a project can be set up from the new manifest design) and, through issues 498 to 503, Easy to use; `docs/design.md#registry-and-adapters` and `docs/design.md#rules`.

## Design Picture

No change to how the parts fit, only to names. `docs/design.md#registry-and-adapters` (manifest-route bullet), the `setup` row of the verb table and `docs/design.md#rules` (project-names row) take the new name in this PR, with one change-log row (ADR-0017).
