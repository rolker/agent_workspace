# Plan: repos-manifest: rename the tool's code, directory and command from ros-manifest

## Issue

https://github.com/rolker/agent_workspace/issues/497

## Context

The manifest tool lives in `tools/ros-manifest/` (package `ros_manifest`, command `ros-manifest`, distribution `ros-manifest`). The owner chose the new name `repos-manifest`; this is the first of seven issues (497 to 503) that build the new manifest design, and 498 rewrites the resolver on the new path. This issue is a pure rename: no change to what the tool reads, writes or does. Owner decisions of 2026-11-18 (progress.md Checkpoint): CI changes cover both places in `validate.yml` that name the tool and nothing else; the Issue Review's points are instructions for this plan; issue 488 lands first and this sweep then covers its files.

## Approach

1. **Start from a current base** — `git fetch origin`, then check `git merge-base --is-ancestor feature/issue-488 origin/main`. If 488 is on `main` (as of planning it is not: its branch is local and unpublished), `git merge origin/main` into this branch before the sweep. If it is not yet, stop and report to the owner that 488 is not on `main`; do not start the sweep (the owner chose 488 first so the path changes once). Re-run the same check at step 11.
2. **Move the directory and package** — `git mv tools/ros-manifest tools/repos-manifest`, `git mv tools/repos-manifest/src/ros_manifest tools/repos-manifest/src/repos_manifest`. Edit `pyproject.toml`: `name = "repos-manifest"`, script `repos-manifest = "repos_manifest.cli:main"`, any package path.
3. **Sweep the names** — path-limited search-and-replace (`ros-manifest` to `repos-manifest`, `ros_manifest` to `repos_manifest`, `ROS_MANIFEST_GIT_TIMEOUT` to `REPOS_MANIFEST_GIT_TIMEOUT`, `.ros-manifest-cache` to `.repos-manifest-cache`) over everything `git grep -il 'ros-manifest\|ros_manifest\|ROS_MANIFEST'` finds outside `.agent/work-plans/` and outside past rows of the `docs/design.md` change log. List, from that search and not from the issue text: the tool's source and 12 test modules; `tools/repos-manifest/README.md`, `docs/design.md`, `docs/prototype.md`, `tests/fixtures/p11/manifest.yaml`; `.agent/project_types/ros2_colcon/adapter.sh` (comments, the `.venv/bin/` path in the resolver-path function, two `make install-ros-manifest` hints, the timeout variable named in a comment); `.agent/projects.local.example`; `Makefile`; `.gitignore`; `docs/design.md`, `docs/manifest/design.md`, `docs/fork_parity.md`, `docs/roadmap.md`; three suites `.agent/scripts/tests/test_ros2_colcon.sh` (35 matches, including the fake resolver at `$sb/.venv/bin/ros-manifest` and `-m ros_manifest.cli`), `test_register_project.sh` (8), `test_fresh_clone_no_project.sh` (3, including the stamp `.make/ros-manifest.done`). The earlier sentence in `docs/manifest/design.md` line 11 about the earlier name `ros-manifest` stays, as the old name's history.
4. **Generated header and fixtures** — `emit.py` writes `# Generated by ros-manifest`; change it to `repos-manifest` (two lines), update `test_layout.py:141`, and regenerate or sed the 14 `.repos` files under `tests/fixtures/p11/expected/{jazzy,rolling}/` that carry the header. Before changing, `git grep -n 'Generated by'` across `.agent/` and `tools/` to show that nothing compares the header text except `test_layout.py` and the fixture comparison in `test_acceptance_p11.py`; the adapter's `validate` compares resolved directories. Say so in the PR.
5. **Makefile** — rename target `install-ros-manifest` to `install-repos-manifest` (also in `.PHONY` and help lines), stamp to `$(STAMP)/repos-manifest.done`, prerequisite `tools/repos-manifest/pyproject.toml`, header comment. Make the stamp's recipe first remove the old install on a machine that has it: `$(VENV_BIN)/python3 -m pip uninstall --quiet -y ros-manifest || true` (venv pip only, ADR-0009), `rm -f $(VENV_BIN)/ros-manifest $(STAMP)/ros-manifest.done`, then install and touch the new stamp. No alias for the old target or command (it would fail the acceptance search). Run `make generate-skills` if `.PHONY` changes alter the `/make_*` command list, and commit the result.
6. **Adapter hint** — the two hints already say `make install-repos-manifest` after the sweep; keep the hint as is (no legacy-path wording): a machine with only the old command is told to run the new target, which then removes the old install. A test in `test_ros2_colcon.sh` covers the not-installed hint with the new name.
7. **CI (`.github/workflows/validate.yml`)** — only these lines, read from the owner's "both jobs" decision: adapter-tests job lines 39 to 41 (step name `Install ros-manifest ...`, `pip install -e tools/ros-manifest`, `ros-manifest --help`) and the tool's own job lines 55 to 71 (job id `validate-ros-manifest`, its `name:`, step name, `pip install -e tools/ros-manifest[test]`, `pytest tools/ros-manifest/tests`). `git diff -U0 .github` is pasted into the PR description as the full list of CI lines changed. Check that branch protection does not name the old job id as a required check (`gh api` on the protection rules); if it does, tell the owner before pushing, since renaming the job id would stall merging.
8. **Docs and design** — in `docs/design.md`: the manifest-route bullet under Registry and adapters (about line 449), the `setup` verb-table row (about line 502), the Rules project-names row (about line 172); not the earlier change-log rows (1042, 1080, 1099, 1103 keep the old name as history). Add one change-log row dated 2026-11-18: the tool is renamed repos-manifest (path, package, command, make target, stamp, env var, cache directory), no behaviour change (#497). `tools/repos-manifest/README.md` gets a short note: the environment variable `ROS_MANIFEST_GIT_TIMEOUT` and the cache directory `.ros-manifest-cache` are ignored after the rename (set `REPOS_MANIFEST_GIT_TIMEOUT`; an old cache directory can be deleted). The PR says the same, and that orphaned `.ros-manifest-cache/` directories show as untracked because the old `.gitignore` entry is gone.
9. **Tests, offline** — `make lint`-style pre-commit on changed files; `.venv/bin/pytest tools/repos-manifest/tests` after `pip install -e tools/repos-manifest[test]` in the venv; the three shell suites above; `.agent/scripts/validate_adapter.sh` for ros2_colcon (ADR-0011) if it runs offline. Per the memory rule for dispatched agents, no full ~10 min pre-commit suite pass; CI runs the suites.
10. **Sandbox proof of the migration** — in a scratch checkout of this branch under the scratchpad, build a venv with the old distribution installed (`pip install -e` of a copy of the old tree from `main`), plus `.make/ros-manifest.done` and `.venv/bin/ros-manifest`; delete the old tree path to mimic the rename; run `make setup` (or `make install-repos-manifest` if `setup` needs the network for git-bug; say which). Show after: `.venv/bin/repos-manifest --help` runs, `.venv/bin/ros-manifest` and the old stamp are gone, `pip show ros-manifest` fails, `pip show repos-manifest` succeeds, and the adapter's manifest route finds the command (the resolver-path test in `test_ros2_colcon.sh`). Paste the transcript into the PR description.
11. **Finish** — `git fetch origin`; run the acceptance search `git grep -n -i 'ros-manifest\|ros_manifest\|ROS_MANIFEST' -- . ':!.agent/work-plans'` on the branch and on `origin/main`; the only hits left are the history sentences (earlier change-log rows, `docs/manifest/design.md` line 11 and this issue's own mentions); list them in the PR. Diff `origin/main` against the branch base for any file that names the old path (a late merge of 488 or another branch); if any, merge `origin/main` and sweep again. The PR description also gives 488's author the replacement command in case 488 does land second after all: `git grep -il 'ros-manifest\|ros_manifest'` on the rebased branch.

## Prior Art

Nothing new is being built. The stamp-file install rule (ADR-0007) and `.venv` rule (ADR-0009) are used as they are. A compatibility alias for the old command was considered and rejected: it keeps the old name alive and fails the acceptance search; the tool has one user.

## Serves

Flexibility (a project can be set up from the new manifest design) and, through issues 498 to 503, Easy to use; `docs/design.md#registry-and-adapters` and `docs/design.md#rules`.

## Design Picture

No change to how the parts fit, only to names. `docs/design.md#registry-and-adapters` (manifest-route bullet), the `setup` row of the verb table and `docs/design.md#rules` (project-names row) take the new name in this PR, with one change-log row (ADR-0017).

## Principles Self-Check

| Principle | Consideration |
|---|---|
| Only what's needed | Pure rename; no behaviour change; no alias or env-var fallback |
| Name the rule before bending it | CI edits limited to the two named places, every changed line listed in the PR |
| Verify before claiming | Migration proven in a sandbox; header-comparison check shown by search; acceptance search run on the branch and on `origin/main` |
| Keep one current design | Design text and change-log row in the same PR; history rows left alone |
